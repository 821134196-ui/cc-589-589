# 社区水井水质采样与送检批次系统

采样员、送检人员、实验室与负责人在同一链条上交接水质样品；居民公告中的检测结论
可一路追溯到**取样地点、取样时间、容器/批次、封签照片与每一次交接记录**。

- 后端：TypeScript + NestJS + Prisma（SQLite）
- 前端：React + Vite（纯 SVG 点位图）
- 封签照片本地磁盘存放；实验室接口本地模拟
- **一条命令启动**：`npm run dev`

## 快速开始

```bash
npm install        # 安装依赖
npm run setup      # 初始化数据库（建表 + 演示种子，可随时执行以恢复演示数据）
npm run dev        # 同时启动后端 http://localhost:3001 与前端 http://localhost:5173
```

打开 http://localhost:5173 。首次启动若数据库为空会自动播种，无需手动 setup。

演示三类（实际是五类）异常处理：

```bash
npm run dev        # 终端 1
npm run demo       # 终端 2：对运行中的后端发起真实 HTTP 请求
```

## 核心业务规则（均在服务端强制）

1. **容器编号全局唯一**——重复登记返回 `409 容器编号冲突`，禁止覆盖旧样品。
2. **交接按实际顺序**——启运送检 → 实验室签收 → 出结果 → 负责人放行；
   跳步办理返回 `409 交接顺序错误`。交接序号逐次递增、只追加。
3. **封签与冷藏核对**——任一环封签破损或冷藏不达标即拒绝继续流转；
   实验室可退样，样品保留为"实验室退样"，**不得用新样本覆盖**。
4. **取样人不能签自己的放行**——本人取样的样品由其他负责人批准，否则 `403`。
5. **结果版本化**——更正只产生新版本，旧结果 `isCurrent=false` 永久保留；
   已更正的结果必须由负责人依据新版本重新批准才能发布公告。
6. **异常结果未复测合格前禁止归档**（`409`）；复测必须使用新容器，
   新旧批次通过复测链关联，报告中可互查。
7. **公告只允许 `ANNOUNCER` 授权人员发布**（无授权 `403`），
   且必须已有负责人"同意发布"决定（否则 `409`）。

## 页面

- **井位地图** `/`：SVG 社区点位图，每口井显示最近一次采样状态（异常/退样带脉冲告警环）
- **采样登记** `/collect`：井号、容器编号、取样时间、现场条件、封签照片上传
- **送检交接** `/handovers`：按待办环节核封签、核冷藏
- **实验室** `/lab`：模拟检测（合格/异常）、手工录入、结果更正
- **负责人审核** `/review`：放行与公告/复测/归档决定
- **居民公告** `/announcements`：授权发布；公告可跳转完整报告
- **报告详情** `/samples/:id`：封签照片、现场条件、交接时间线、结果版本链、
  复测链、负责人决定、公告记录
